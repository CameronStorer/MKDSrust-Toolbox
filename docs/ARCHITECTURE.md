# Stage 1 implementation notes

`nitro-formats` has bounded, offset-bearing readers without UI or filesystem dependencies. Parsed resources retain
their original representation, metadata, unknown sections and padding. Unchanged writes are exact; NARC updates
splice same-size members and CARC updates retain the builder's minimal-change LZ77 token groups. BMG exposes UTF-16
units and opaque escape tokens. NSBTX is read-only, with explicit texture and palette selection.

`toolbox-core` owns the ROM bytes, virtual archive tree, project, undo cursor, validation and packaging. The ROM is
read once and never extracted during browsing. `project.toml` records the SHA-256 and a local ROM-path hint. Opening
a project checks the hash. Changed palette entries and BMG messages are stored as editable JSON under `edits/`,
with per-file source hashes; unchanged colours, messages and file metadata stay in the ROM. Paths through archives use the containing
archive's name as a directory. Other binary replacements are persisted as BSDIFF source deltas; author-created
new files contain their own bytes. Archive roots are rebuilt in memory when packing. New archive members are outside
Stage 1; new top-level game-format files can be added through the core project API / edits folder.

The app calls typed commands generated by tauri-specta. File bytes and PNGs use one-shot, bounded in-memory URLs on
the `toolbox` custom protocol, never JSON arrays or extracted files in the project. Long operations run on Tauri's
blocking pool. All edits, manifest changes and reverts use a single apply/revert history. Commands persist edits
immediately; undo history itself is session-local. Reopening the app retains edits, settings and workspace layouts.

Each workspace is a dockview layout. The frontend holds only view state, selections and editor drafts. Saved panel
layouts and keybindings can be reset/rebound. The mocked backend is selected only with `VITE_MOCK_BACKEND=1` and
visibly marked; its metadata and image originate in the Rust synthetic fixture generator. It never opens a ROM.

Packing is deterministic. Original ROM targets always become BSDIFF40 patches, author-created paths become `add`
entries after format and retail similarity checks. Zip limits, portable path rules, symlink checks and manifest
validation run before output. Large patch ratios produce manual-review warnings. Stage 1 cannot assert complete
DS compatibility, so DS claims are downgraded to PC with a warning. Launcher quarantine and moderation remain
external to Toolbox.
The optional `platforms` field is omitted for the default PC claim, preserving compatibility with older v1
launchers that reject unknown fields; project metadata and typed IPC still retain the explicit platform setting.

The local opt-in integration test uses `MKDS_ROM`, skips without it and performs all ROM-derived work in memory.
CI and browser captures exclusively use generated fixtures. The required fonts and OFL notices are bundled by Vite.
The browser backend's messages, tile indices and hex bytes are emitted by the same Rust generator, and its palette
preview updates when edited. Playwright owns Vite through a global setup/teardown so no shell process tree is left
running after capture. Default captures use Vite's dev server; restricted environments can select production preview.
